4.1 - IAM en AWS

IAM: quien puede hacer que

En AWS, IAM (Identity and Access Management) define los permisos con politicas escritas en JSON. Cada politica dice: estas acciones, sobre estos recursos, permitidas o negadas.

En este curso, tu instructor te dio un usuario IAM con permiso de crear y ejecutar Lambda en su cuenta, y nada mas. Asi practicas sin riesgo de costo.

  "Resource": "*"

boto3 y S3

El SDK de Python para hablar con AWS

4.2 - boto3

boto3: tu control remoto de AWS

boto3 es la libreria oficial de Python para AWS. Con ella hablas con cualquier servicio: S3, Lambda, Redshift. Es el equivalente a google-cloud-*.

El patron es siempre el mismo: creas un cliente de un servicio y llamas sus metodos.


import boto3

# un cliente por servicio
s3 = boto3.client("s3")
lam = boto3.client("lambda")

# subir un archivo a S3
s3.upload_file("ventas.csv",
               "mi-bucket",
               "entrada/ventas.csv")
Las credenciales (tu llave de acceso IAM) se configuran una vez; boto3 las usa automaticamente.

4.2 - S3

S3: el data lake de AWS

Es el mismo concepto que Cloud Storage del Cap 3: almacenamiento de objetos, barato y duradero. Aqui aterrizan los datos crudos antes de procesarse.

S3 es ademas el disparador mas comun de pipelines: cuando llega un archivo, S3 puede lanzar una Lambda automaticamente. Eso veremos enseguida.

Lambda

ETL serverless dirigido por eventos

4.3 - Lambda

Lambda: el FaaS de AWS

Recuerda el FaaS del Cap 1: subes una funcion, se ejecuta por un evento, se apaga al terminar, pagas solo los milisegundos que corre. Lambda es eso en AWS.

  • 1 millon de invocaciones al mes gratis SIEMPRE
  • Lenguajes: Python, Node.js, Go, Java
  • Se dispara por eventos: archivo en S3, mensaje en cola, llamada HTTP
  • Limite de ejecucion: 15 minutos por invocacion
Esto lo practicas tu. Tu instructor te dio acceso IAM para crear y ejecutar Lambdas en su cuenta. Es el equivalente AWS de las Cloud Functions de GCP.
CAP 4 - 4.3 LAMBDA
4.3 - Anatomia de una Lambda

Una funcion Lambda en Python

Toda Lambda tiene un handler: la funcion que AWS llama cuando ocurre el evento. Recibe event (los datos del disparador) y context.

El event es como llega la informacion del disparador: si fue un archivo en S3, ahi viene el nombre del bucket y del archivo. 

def lambda_handler(event, context):
    # procesar lo que llego en el evento
    registros = event.get("registros", [])
    total = sum(r["monto"] for r in registros)

    return {
        "statusCode": 200,
        "total": total,
        "procesados": len(registros)
    }

4.4 - AWS Glue

Glue: ETL gestionado con Spark

Lambda es genial para tareas ligeras y rapidas. Pero para transformar volumenes grandes, AWS ofrece Glue: ETL gestionado que corre Apache Spark por debajo, sin que administres el cluster.

  • Crawler: detecta el esquema de tus datos en S3
  • Data Catalog: un indice de tus datasets
  • Jobs: transformaciones en PySpark
Glue tiene costo y no hay capa gratuita comoda. Por eso en el curso lo veras como demo del instructor. Tu practicaras el mismo PySpark, pero corriendolo local en Colab (gratis). DEMO

4.5 - Step Functions

Cuando un pipeline tiene varios pasos

Una Lambda hace una cosa. Pero un pipeline real tiene varios pasos que deben correr en orden, con reintentos si algo falla. Step Functions los coordina.

Es el DAG del Cap 2 hecho servicio: define el flujo de tareas, su orden y que hacer ante errores. El equivalente en GCP seria Cloud Composer (Airflow).
