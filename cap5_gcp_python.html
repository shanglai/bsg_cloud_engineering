Batch vs tiempo casi real

Dos ritmos para mover datos

5.1 - Dos patrones

No todos los datos corren al mismo ritmo

Batch (por lotes)
Procesas grandes volumenes juntos, cada cierto tiempo. Ej: todas las ventas del dia, cada noche. Herramientas: Dataflow, Data Fusion.
Tiempo casi real (NRT)
Procesas cada dato apenas llega, en segundos. Ej: un pedido entra y se registra al instante. Herramienta: Cloud Functions.
La pregunta de diseno: cuanto puede esperar el dato. Si la respuesta es "horas", batch. Si es "segundos", tiempo casi real. Hoy practicas ambos.

5.2 - Cloud Functions

Cloud Functions: el primo de Lambda

El FaaS de GCP. Igual que Lambda en AWS: subes una funcion, se dispara por un evento, pagas solo lo que corre. 2 millones de invocaciones al mes gratis.

  • Se dispara por: archivo en GCS, mensaje en Pub/Sub, HTTP
  • Lenguajes: Python, Node, Go, Java
  • Gen2: corre sobre Cloud Run, mas potente
La gran ventaja sobre Lambda: usa la service account del proyecto automaticamente. No tienes que crear ni pasar un rol de ejecucion. Menos friccion. 2M GRATIS

5.2 - El pipeline NRT

Archivo llega, dato aterriza en BigQuery

El patron en tiempo casi real que practicaras: cada archivo que llega a GCS dispara una funcion que lo carga a BigQuery, en segundos.

Es el mismo patron event-driven de Lambda (Cap 4) y de Pub/Sub (Lab 2), ahora con GCS y Cloud Functions. Esto lo practicas en tu propio proyecto, gratis.
CAP 5 - 5.2 PIPELINE NRT
5.2 - El codigo

Una Cloud Function disparada por GCS


import functions_framework
from google.cloud import bigquery

@functions_framework.cloud_event
def cargar_a_bq(cloud_event):
    # El evento trae el nombre del archivo que llego a GCS
    datos = cloud_event.data
    bucket = datos["bucket"]
    archivo = datos["name"]

    client = bigquery.Client()
    uri = f"gs://{bucket}/{archivo}"

    # Cargar el CSV directo a una tabla de BigQuery
    config = bigquery.LoadJobConfig(
        source_format="CSV", skip_leading_rows=1, autodetect=True)
    client.load_table_from_uri(
        uri, "mi_dataset.ventas", job_config=config).result()
El decorador @functions_framework.cloud_event conecta la funcion al evento. Cuando llega un archivo, GCS la dispara con los datos del archivo.

5.3 - Apache Beam

Beam: un modelo, batch o streaming

Apache Beam es un modelo de programacion para pipelines de datos. Escribes la logica una vez y corre igual en batch o en streaming. Dataflow es el servicio de GCP que ejecuta pipelines Beam, a escala y gestionado.

Recuerda "dividir, procesar, combinar" del Cap 2. Beam es justo eso: reparte los datos entre muchas maquinas, los transforma en paralelo y junta el resultado. 

import apache_beam as beam

with beam.Pipeline() as p:
    (p
     | beam.Create([1, 2, 3, 4])
     | beam.Map(lambda x: x * 10)
     | beam.Map(print))
# imprime 10, 20, 30, 40
Lo practicaras con el DirectRunner (Beam local en Colab, gratis). El mismo codigo correria en Dataflow cambiando una linea.

5.4 - Cloud Data Fusion

Data Fusion: pipelines arrastrando cajas

Data Fusion es el ETL visual de GCP: construyes pipelines arrastrando y conectando nodos, sin escribir codigo. Por debajo genera y corre pipelines (basados en CDAP/Spark).

Es el equivalente conceptual de Glue Studio en AWS: misma idea de ETL gestionado y visual.

Data Fusion tiene costo (la instancia cobra por hora, sin capa gratuita comoda). Por eso lo veras como demo del instructor. Tu practicaras el mismo concepto batch con Beam local. DEMO

Gemini en BigQuery y Vertex AI

5.5 - Preparacion de datos

Limpiar datos con ayuda de Gemini

BigQuery data preparation usa Gemini para sugerirte transformaciones de limpieza: separar columnas, aplanar JSON, corregir tipos, unir tablas. Es low-code: aceptas o ajustas las sugerencias.

Recuerda el ETL "transform" del Cap 4: lo que ahi hiciste a mano con PySpark, aqui Gemini te lo sugiere sobre tus tablas de BigQuery. Dataform agenda esas preparaciones.
Lo veras en la demo junto con Data Fusion: requiere habilitar la API de Gemini for Google Cloud y permisos IAM. Es la forma moderna de preparar datos sin escribir cada transformacion. DEMO

Del pipeline al modelo: Vertex AI

Vertex AI es la plataforma de ML de GCP. Los datos que preparaste y guardaste en BigQuery alimentan modelos mas avanzados que los de BQML.
