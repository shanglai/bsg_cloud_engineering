¿Qué es la computación en la nube?

La idea central, sin tecnicismos

1.1 · Definición

Pagar por usar, no por poseer

La nube es acceso bajo demanda a recursos de cómputo —servidores, almacenamiento, bases de datos, redes— a través de internet, sin administrar el hardware físico.

Analogía: no compras una planta eléctrica para tu casa. Te conectas a la red y pagas la luz que consumes. La nube es eso, para cómputo.
CAP 1 · 1.1 DEFINICIÓN
1.1 · Conceptos esenciales

Tres palabras que repetiremos todo el curso

Elasticidad
Crece y se reduce según la demanda. 1 servidor a medianoche, 50 en hora pico — automático.
Escalabilidad
Capacidad de manejar más datos sin rediseñar. De 1 GB a 1 PB con la misma arquitectura.
Disponibilidad
Sistemas distribuidos y tolerantes a fallos. Si un servidor cae, otro responde.
Para ingeniería de datos esto significa: ejecutar pipelines y ETL sobre millones de registros sin comprar ni mantener un solo servidor.

Modelos de servicio

IaaS · PaaS · SaaS · FaaS — ¿quién administra qué?

1.2 · La pregunta clave

Todo se reduce a: ¿quién administra qué?

Mientras más subes de IaaS a SaaS, menos administras tú y más administra el proveedor. Ganas velocidad, cedes control.

CAP 1 · 1.2 ANALOGÍA
1.2 · IaaS

IaaS — Infraestructura como servicio

Te dan los ladrillos crudos: máquinas virtuales, redes, discos. Tú instalas el sistema operativo y todo lo demás.

Ejemplos:
AWS → EC2
GCP → Compute Engine

Cuándo usarlo
Cuando necesitas control total: una configuración especial, software heredado, o un entorno muy específico.
Cuidado: tú eres responsable de parches, seguridad y de apagar la máquina. Una VM olvidada encendida = factura sorpresa.
CAP 1 · 1.2 IaaS
1.2 · PaaS y SaaS

PaaS y SaaS — menos plomería

PaaS · Plataforma
Subes tu código o tus datos; el proveedor corre el servidor, el SO y el runtime.

Ej: Redshift, BigQuery, Azure Synapse. Tú escribes SQL, ellos manejan el clúster.
SaaS · Software
Aplicación lista para usar desde el navegador. No instalas ni administras nada.

Ej: Power BI, Looker, Salesforce, Gmail.
En ingeniería de datos vivimos sobre todo en PaaS y FaaS: queremos escribir lógica de datos, no administrar servidores.
CAP 1 · 1.2 PaaS / SaaS
1.2 · FaaS

FaaS — funciones sin servidor

Subes una función. Se ejecuta sola cuando ocurre un evento y se apaga al terminar. Pagas solo los milisegundos que corre.

Ejemplos:
AWS → Lambda
GCP → Cloud Functions

Este es el corazón de los capítulos 4 y 5: un archivo llega → se dispara una función → limpia y carga los datos.

CAP 1 · 1.3 ARQUITECTURA
1.3 · Por qué a la empresa le importa

CAPEX vs OPEX, en una línea

CAPEX · comprar
Inversión grande por adelantado en hardware. Se deprecia lento. El modelo del data center propio.
OPEX · rentar
Gasto mensual variable según uso. Sin inversión inicial. El modelo de la nube — pagas lo que consumes.
La nube convierte un gran CAPEX en OPEX flexible. Por eso un proyecto puede arrancar hoy sin comprar un solo servidor — y por eso a nosotros nos sale gratis para aprender.

CAP 1 · 1.4 EQUIVALENCIAS
1.4 · ¿En qué brilla cada uno?

Fortalezas, sin religión de marca

AWS
El más maduro y amplio (200+ servicios). Domina en data lakes y arquitecturas event-driven. Ideal para cargas críticas y proyectos de gran escala.
GCP
Sobresale en Big Data, analítica y ML. BigQuery es referencia mundial. Precios competitivos y muy amigable para empezar.
Para este curso usaremos los dos, pero la práctica del alumno se apoyará más en GCP por una razón muy concreta: la veremos en la siguiente sección.

05

Cómo trabajaremos

Capa gratuita, Web UI y Colab — sin gastar

1.5 · La regla de oro

Aprenderemos sin pagar — con cuidado

GCP — nuestra base
BigQuery sandbox: 1 TB de consultas al mes, sin tarjeta de crédito. Cloud Functions: 2M ejecuciones gratis. Es el entorno más seguro para clase.
AWS — con tope
Cuentas nuevas: $100 en créditos, plan gratis por 6 meses. Lambda y S3 siempre-gratis dentro de límites. Siempre con budget alert de $1.
Trampas de cobro en AWS para principiantes: NAT Gateways (~$33/mes), IPs sin usar y recursos huérfanos. Regla: si lo encendiste, sabes cómo apagarlo.
CAP 1 · 1.5 CAPA GRATUITA
1.5 · Dos herramientas, una regla simple

¿Consola o Colab?

Web UI / Consola CLICK
Para crear y ver recursos: un bucket, un proyecto, ver el job de una función. Lo que se hace con clics.
Google Colab CÓDIGO
Para todo lo que es Python: SDKs, ETL, PySpark, consultas. No instalas nada, corre gratis en el navegador.
Regla: lo que es clic → consola. Lo que es código → Colab. Lo que cuesta dinero (Glue, Data Fusion, Redshift) → solo demo del instructor.
CAP 1 · 1.5 HERRAMIENTAS
1.5 · Tu primera línea de nube

Así de simple se ve conectarse

Listar los datasets públicos de BigQuery desde Colab — sin servidores, sin tarjeta:


from google.cloud import bigquery

client = bigquery.Client(project="mi-proyecto")

# Consultar un dataset público — corre en segundos
query = """
    SELECT name, SUM(number) AS total
    FROM `bigquery-public-data.usa_names.usa_1910_2013`
    WHERE state = 'TX'
    GROUP BY name
    ORDER BY total DESC
    LIMIT 5
"""
for row in client.query(query):
    print(row.name, row.total)
Esto es ingeniería de datos en la nube: SQL sobre millones de filas, orquestado desde Python, sin administrar un solo servidor.
