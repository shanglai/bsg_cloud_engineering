Que es la computacion en la nube

La idea central, sin tecnicismos

1.1 - Definicion

Pagar por usar, no por poseer

La nube es acceso bajo demanda a recursos de computo -servidores, almacenamiento, bases de datos, redes- a traves de internet, sin administrar el hardware fisico.

Analogia: no compras una planta electrica para tu casa. Te conectas a la red y pagas la luz que consumes. La nube es eso, para computo.
CAP 1 - 1.1 DEFINICION
1.1 - Conceptos esenciales

Tres palabras que repetiremos todo el curso

Elasticidad
Crece y se reduce segun la demanda. 1 servidor a medianoche, 50 en hora pico, automatico.
Escalabilidad
Capacidad de manejar mas datos sin redisenar. De 1 GB a 1 PB con la misma arquitectura.
Disponibilidad
Sistemas distribuidos y tolerantes a fallos. Si un servidor cae, otro responde.
Para ingenieria de datos esto significa: ejecutar pipelines y ETL sobre millones de registros sin comprar ni mantener un solo servidor.

CAP 1 - 1.2 ANALOGIA
1.2 - IaaS

IaaS - Infraestructura como servicio

Te dan los ladrillos crudos: maquinas virtuales, redes, discos. Tu instalas el sistema operativo y todo lo demas.

Ejemplos:
AWS: EC2
GCP: Compute Engine

Cuando usarlo
Cuando necesitas control total: una configuracion especial, software heredado, o un entorno muy especifico.
Cuidado: tu eres responsable de parches, seguridad y de apagar la maquina. Una VM olvidada encendida es una factura sorpresa.
CAP 1 - 1.2 IaaS
1.2 - PaaS y SaaS

PaaS y SaaS - menos plomeria

PaaS - Plataforma
Subes tu codigo o tus datos; el proveedor corre el servidor, el SO y el runtime.

Ej: Redshift, BigQuery, Azure Synapse. Tu escribes SQL, ellos manejan el cluster.
SaaS - Software
Aplicacion lista para usar desde el navegador. No instalas ni administras nada.

Ej: Power BI, Looker, Salesforce, Gmail.
En ingenieria de datos vivimos sobre todo en PaaS y FaaS: queremos escribir logica de datos, no administrar servidores.
CAP 1 - 1.2 PaaS / SaaS
1.2 - FaaS

FaaS - funciones sin servidor

Subes una funcion. Se ejecuta sola cuando ocurre un evento y se apaga al terminar. Pagas solo los milisegundos que corre.

Ejemplos:
AWS: Lambda
GCP: Cloud Functions

Este es el corazon de los capitulos 4 y 5: un archivo llega, se dispara una funcion, limpia y carga los datos.

CAP 1 - 1.3 ARQUITECTURA
1.3 - Por que a la empresa le importa

CAPEX vs OPEX, en una linea

CAPEX - comprar
Inversion grande por adelantado en hardware. Se deprecia lento. El modelo del data center propio.
OPEX - rentar
Gasto mensual variable segun uso. Sin inversion inicial. El modelo de la nube: pagas lo que consumes.
La nube convierte un gran CAPEX en OPEX flexible. Por eso un proyecto arranca hoy sin comprar un servidor, y por eso a nosotros nos sale gratis para aprender.

1.4 - En que brilla cada uno

Fortalezas, sin religion de marca

AWS
El mas maduro y amplio (200+ servicios). Domina en data lakes y arquitecturas event-driven. Ideal para cargas criticas y proyectos de gran escala.

Como trabajaremos

Capa gratuita, Web UI y Colab - sin gastar

1.5 - La regla de oro

Aprenderemos sin pagar, con cuidado

GCP - nuestra base
BigQuery sandbox: 1 TB de consultas al mes, sin tarjeta de credito. Cloud Functions: 2M ejecuciones gratis. Es el entorno mas seguro para clase.
AWS - con tope
Cuentas nuevas: 100 USD en creditos, plan gratis por 6 meses. Lambda y S3 siempre-gratis dentro de limites. Siempre con budget alert de 1 USD.
Trampas de cobro en AWS para principiantes: NAT Gateways (~33 USD/mes), IPs sin usar y recursos huerfanos. Regla: si lo encendiste, sabes como apagarlo.

CAP 1 - 1.5 HERRAMIENTAS
1.5 - Tu primera linea de nube

Asi de simple se ve conectarse

Listar datos publicos de BigQuery desde Colab, sin servidores, sin tarjeta:


from google.cloud import bigquery

client = bigquery.Client(project="mi-proyecto")

# Consultar un dataset publico - corre en segundos
query = """
    SELECT name, SUM(number) AS total
    FROM `bigquery-public-data.usa_names.usa_1910_2013`
    WHERE state = 'TX'
    GROUP BY name
    ORDER BY total DESC
    LIMIT 5
"""
for row in client.query(query):
    print(row.name, row.total)
Esto es ingenieria de datos en la nube: SQL sobre millones de filas, orquestado desde Python, sin administrar un solo servidor.
