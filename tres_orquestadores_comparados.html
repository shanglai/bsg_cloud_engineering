La idea de hoy

El mismo concepto, tres herramientas

Ya sabes que es un DAG y para que sirve orquestar. Hoy ves que el mismo pipeline de 3 pasos se expresa en tres orquestadores distintos. La logica es identica; cambia la sintaxis y la filosofia.

  • AIRFLOW el estandar, en Python DEMO
  • WORKFLOWS serverless GCP, en YAML PRACTICA
  • STEP FUNCTIONS serverless AWS, en JSON DEMO
Al ver los tres lado a lado, la leccion se vuelve clara: orquestar es un concepto, no una herramienta. Si lo dominas, saltas entre plataformas sin re-aprender.

ORQUESTADORES - EL PIPELINE
01

Airflow

El estandar de industria, en Python (demo)

1 - Airflow DEMO

El pipeline en Airflow (Python)

Airflow define el DAG en Python. Cada paso es un operador; las dependencias con >>. Es el mas potente y el mas usado, pero necesita un entorno corriendo (Composer cuesta; por eso hoy es demo local).

Fortaleza: ecosistema enorme, cientos de operadores, ideal para pipelines complejos. Costo: alto si es gestionado. 

with DAG("pipeline",
    schedule="@daily",
    start_date=datetime(2026,1,1)) as dag:

    e = PythonOperator(
        task_id="extraer",
        python_callable=extraer)
    t = PythonOperator(
        task_id="transformar",
        python_callable=transformar)
    n = PythonOperator(
        task_id="notificar",
        python_callable=notificar)

    e >> t >> n
ORQUESTADORES - 1 AIRFLOW
02

Cloud Workflows

Serverless de GCP, en YAML (practica)

2 - Cloud Workflows GCP PRACTICA

El pipeline en Workflows (YAML)

Cloud Workflows define el flujo en YAML. Serverless: sin entorno permanente, cobra por paso (casi gratis). Ideal para flujos ligeros que encadenan APIs y servicios de GCP.

Fortaleza: barato, cero infraestructura, rapido de montar. Limite: menos ecosistema que Airflow para pipelines muy complejos. 

main:
  steps:
    - extraer:
        assign:
          - datos: "registros crudos"
    - transformar:
        assign:
          - limpio: ${datos + " procesado"}
    - notificar:
        return: ${"listo: " + limpio}
Hoy tu practicas este: lo despliegas y ejecutas en tu proyecto GCP.
ORQUESTADORES - 2 WORKFLOWS
03

Step Functions

Serverless de AWS, en JSON (demo)

3 - Step Functions AWS DEMO

El pipeline en Step Functions (JSON)

Step Functions define el flujo en JSON (Amazon States Language). Es el equivalente AWS de Workflows: serverless, por transicion, con capa gratuita. Cada estado suele invocar una Lambda.

Fortaleza: integracion profunda con servicios AWS, visualizacion del flujo. Filosofia: maquina de estados, no "grafo de tareas Python". 

{
 "StartAt": "Extraer",
 "States": {
  "Extraer": {
   "Type": "Pass",
   "Result": "datos crudos",
   "Next": "Transformar" },
  "Transformar": {
   "Type": "Pass",
   "Result": "datos limpios",
   "Next": "Notificar" },
  "Notificar": {
   "Type": "Pass",
   "End": true }
 }
}

ORQUESTADORES - 4 COMPARACION
4 - El criterio

Como elegir en el mundo real

  • ¿Ya vives en Airflow o tienes pipelines complejos? Quedate en Airflow (o Composer/MWAA).
  • ¿Flujo simple, en GCP, quieres barato y rapido? Cloud Workflows.
  • ¿Flujo simple, en AWS, coordinando Lambdas? Step Functions.
  • ¿Empiezas de cero y no sabes? Arranca con el serverless de tu nube; migra a Airflow si crece.
No hay "el mejor". Hay el adecuado para tu nube, tu complejidad y tu presupuesto. Saber los tres te deja elegir con criterio, no por moda.
ORQUESTADORES - 4 CRITERIO
Cierre de la sesion

Lo que te llevas

  • El mismo pipeline se expresa en Python, YAML o JSON segun el orquestador
  • Airflow: potente, ecosistema enorme, pero pesado y caro
  • Cloud Workflows: serverless GCP, barato, para flujos ligeros
  • Step Functions: serverless AWS, maquina de estados, integra Lambdas
  • Orquestar es un concepto transferible, no una herramienta
